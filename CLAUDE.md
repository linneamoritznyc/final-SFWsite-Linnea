# Soil Food Web Foundation: launch preview of soilfoodweb.com

This repo is a review preview of the launch site. It looks like new.soilfoodweb.com
(the WordPress staging site the team builds), uses the launch URLs, fixes the bugs
found on staging, and keeps this repo's copy where staging is thin. The team reads
/review/ to see what changed on each page. Rules below replace the earlier design
and copy rules (3 October 2026 brief).

Read first: /review/ (src/review-notes.html and each page's front matter),
content/staging/README.md, docs/copy-deck-v2.md (this repo's copy and decisions),
and, on branch claude/staging-reality, docs/staging-reality.md (Fable's staging audit).

## How the site is built
- Static HTML. One stylesheet `css/site.css` (tokens in :root), one script `js/site.js`.
  No framework, no runtime build: the HTML in the repo is what Vercel serves.
- Pages are generated by `python3 tools/site/build.py` and committed. Never hand-edit
  a generated `*/index.html`; edit the source and rebuild.
  - `src/pages/*.html`: one fragment per main page, with front matter
    (path, title, description, source, bugs, notes). `{{img src="..." alt="..."}}`
    inserts an image; `{{name args}}` calls a generator in `tools/site/gens.py`
    (courses, team, news, events, publications, playlists, directory, funding, video).
  - Item pages (team-member, directory-member, video, calendar-event, publication,
    blog posts, category) are generated from `content/staging/*.json`.
  - `content/staging/` is a dated snapshot of staging made by
    `tools/staging/extract.py <cache>` from saved pages and the WordPress REST API.
    Re-run it to refresh; the build never reads the network for copy.
  - `content/repo-posts.json` holds posts that exist only in this repo.
- Every page sits at its launch address as `folder/index.html`; `vercel.json` has
  `trailingSlash: true` and redirects this repo's and staging's old addresses.
- `robots.txt` disallows everything and every page has `noindex`: this is a preview.

## Copy
- Staging page with 300+ words of main content: staging text and section order, with
  the brief's fixes. Under 300 words or missing: this repo's version (old pages are in
  `_dev/legacy-pages/`, data in `content/*.json`, `docs/copy-deck-v2.md`). New pages:
  only facts found in this repo or in a brief. Mark the source in front matter.
- Never invent a number, name, price or date. A missing fact is a visible
  `<p class="todo">what is needed, who supplies it</p>`; it shows on the page and is
  listed on /review/.
- Site-wide text fixes live in `FIXES` in tools/site/gens.py (BioComplete™, 100+
  countries, Online Courses, @soilfoodweb.com, Soil Sponge Workshop, no zero-width
  spaces, no em dashes). Staging links are mapped to launch URLs by `staging_link()`.
- One student figure (10,000+, to verify), "100+ countries", and "The Soil Food Web
  School is a program of the Soil Food Web Foundation" everywhere. The funding sentence
  (copy deck section 5) appears on Home, About, Programs, Donate, Scholarship, footer.
- No em dashes. One H1 per page. Footer legal block on every page (EIN 39-4439236,
  Oregon DOJ #71264, address).
- Publication "Why read it" lines are drafts (class "draft"; `?review` highlights them)
  for Carla Portugal; export in docs/publications-blurbs.csv.

## Design
- Matches the staging child theme: Montserrat headings, Source Sans 3 body (self-hosted
  in fonts/), Soil Brown #4F3433, Food Web Green #156826, Light Green #59A66C,
  Organic Cream #F4F1EA, body #333130, ground #231F1D, gold Donate. Buttons use the
  staging radius 1.9em .6em with the hover flip.
- Light Green is 3:1 on white: large numbers and decoration only, never small text.
- Add CSS only for a component that does not exist yet; reuse the classes in site.css.

## Images
- `tools/site/images.py` resolves every image: img/replacements/ first, then the same
  picture already in this repo (matched by name AND by perceptual hash, largest copy
  wins), and only then a download from staging. Output is WebP in img/, at most
  1600 px wide and under 300 KB. `content/staging/images.json` records each source.
- Alt text comes from image-descriptions.csv (sweet-babbage inventory), then
  content/alt.json, then the page. Screenshots and low-resolution sources are flagged
  on /review/. Retired QR codes stay retired.
- Supplied photos and diagrams go in img/new-2026-10/ (originals, not deployed) and are placed
  with `{{photo file="..." alt="..." caption="..." eager}}`: WebP and JPG at 1600 and 800 px
  wide in img/new/ (picture + srcset, under 300 KB, no EXIF, no upscaling, never cropped to hide a BioRender credit).
  Microscope photos get a short caption; diagrams and R5A shoot photos get none (SFW holds the
  rights to the R5A shoot). `name="..."` sets a plain output name; `card` stops at 1200 px.
  A second photo can overlap the first for depth: `<div class="layered">main<div class="layered__inset">...</div></div>`.
  Every placed supplied image gets a row in docs/image-log-additions.csv for Stephanie's log
  (never a personal Drive link in the Link column). Bring an image from another branch only
  if a page needs it.

2. Screenshot changed pages at 1440 and 390 with Playwright
   (executablePath /opt/pw-browsers/chromium), look, fix.
3. Work on main, commit and push after each finished page. Leave other branches alone.
